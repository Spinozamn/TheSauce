1. RESUMEN GENERAL
------------------

TheSauce es una plataforma web de crowdfunding para administrar innovaciones
locales. El sistema permite registrar usuarios, proyectos de innovación,
categorías, etiquetas, contribuciones económicas, carritos, listas de deseos,
comentarios, notificaciones y logs del sistema.

El proyecto tiene dos áreas principales:

1) Área pública y de autenticación:
   - Página de bienvenida.
   - Registro e inicio de sesión.
   - Verificación de correo.
   - Recuperación de contraseña.
   - Autenticación de dos factores.
   - Passkeys.
   - Administración de perfil, seguridad y equipos.

2) Panel administrativo:
   - Dashboard.
   - Roles.
   - Usuarios.
   - Cuentas sociales.
   - Categorías.
   - Etiquetas.
   - Innovaciones.
   - Hitos financieros.
   - Listas de deseos.
   - Carritos.
   - Detalles de carritos.
   - Contribuciones.
   - Comentarios.
   - Notificaciones.
   - Logs del sistema.

El frontend utiliza React con TypeScript. Laravel sirve como backend, API
interno, sistema de autenticación, capa de persistencia y servidor de las
respuestas Inertia.

4. INSTALACIÓN INICIAL
----------------------

Requisitos:
- PHP 8.3 o superior.
- Composer.
- Node.js y npm.
- MySQL si se desea utilizar la configuración actual del usuario.
- Git.

Instalación de dependencias PHP:

    cd /Users/manuel/TheSauce
    composer install

Instalación de dependencias JavaScript:

    npm install

Crear el archivo de entorno:

    cp .env.example .env

Generar la clave de Laravel:

    php artisan key:generate

Configurar la base de datos en .env. Para MySQL:

    DB_CONNECTION=mysql
    DB_HOST=127.0.0.1
    DB_PORT=3306
    DB_DATABASE=thesauce
    DB_USERNAME=root
    DB_PASSWORD=

Los valores de DB_USERNAME y DB_PASSWORD deben coincidir con la instalación
local de MySQL.

Ejecutar migraciones y datos de prueba:

    php artisan migrate:fresh --seed

Compilar frontend:

    npm run build

Iniciar el servidor de desarrollo:

    php artisan serve

En otra terminal, iniciar Vite para desarrollo frontend:

    npm run dev

En el navegador se puede acceder normalmente a:

    http://127.0.0.1:8000


5. CREDENCIALES DE PRUEBA
--------------------------

El seeder crea un usuario para el sistema de autenticación principal:

    Correo:      test@example.com
    Contraseña:  password

Estas credenciales pertenecen al modelo App\Models\User y se utilizan para
entrar al panel protegido.

La contraseña se guarda hasheada mediante el cast de contraseña definido en
el modelo User y/o mediante la fábrica de usuarios.

Si se cambia la contraseña en el código, hay que reconstruir la base de datos
o crear un usuario nuevo con Tinker.

Ejemplo:

    php artisan tinker

    App\Models\User::factory()->create([
        'name' => 'Administrador',
        'email' => 'admin@example.com',
        'password' => 'password',
    ]);


6. AUTENTICACIÓN Y ACCESO AL PANEL
-----------------------------------

La configuración de autenticación se encuentra en config/auth.php.

El guard principal se llama web y utiliza sesiones:

    web -> session -> provider users -> App\Models\User

El middleware auth impide el acceso a usuarios no autenticados.
El middleware verified exige correo verificado para las rutas administrativas.

Las rutas del panel se encuentran en routes/web.php y están agrupadas con:

    auth
    verified

Por lo tanto, si una cuenta no está autenticada o no tiene correo verificado,
Laravel puede redirigirla al login o impedir el acceso.

El proyecto también incluye:
- Fortify.
- Verificación de correo.
- Recuperación de contraseña.
- Dos factores.
- Passkeys.
- Administración de sesiones y seguridad.

13. FRONTEND INERTIA
--------------------

Inertia conecta Laravel y React sin obligar a construir una API REST
separada para cada pantalla.

El flujo de una página administrativa es:

1. El navegador solicita una ruta como /admin/contribuciones.
2. Laravel aplica auth y verified.
3. El controlador consulta los modelos y relaciones.
4. El controlador devuelve Inertia::render().
5. Inertia carga el componente React correspondiente.
6. React presenta los datos en una tabla.

Cada página de módulo se encuentra en una ruta equivalente:

    resources/js/pages/admin/roles/index.tsx
    resources/js/pages/admin/usuarios/index.tsx
    resources/js/pages/admin/cuentas-sociales/index.tsx
    resources/js/pages/admin/categorias/index.tsx
    resources/js/pages/admin/etiquetas/index.tsx
    resources/js/pages/admin/innovaciones/index.tsx
    resources/js/pages/admin/hitos-financieros/index.tsx
    resources/js/pages/admin/lista-deseos/index.tsx
    resources/js/pages/admin/carritos/index.tsx
    resources/js/pages/admin/carrito-detalles/index.tsx
    resources/js/pages/admin/contribuciones/index.tsx
    resources/js/pages/admin/comentarios/index.tsx
    resources/js/pages/admin/notificaciones/index.tsx
    resources/js/pages/admin/logs-sistema/index.tsx

Componentes compartidos:

    resources/js/components/paginacion.tsx

Funciones compartidas:

    resources/js/lib/formato.ts

Tipos del panel:

    resources/js/types/admin.ts

Los tipos TypeScript describen la forma de los datos enviados por Laravel,
incluyendo paginadores y relaciones anidadas.

- Mostrar estados mediante badges de colores.
- Mostrar valores nulos como un guion.

Los IDs internos nunca deben ser la única información visible cuando existe
una relación disponible. Por ejemplo:

Correcto:

    Administrador
    Tecnología
    Proyecto de purificación de agua

No ideal:

    rol_id = 1
    categoria_id = 4
    innovacion_id = 22

18. SOLUCIÓN DE ERRORES CONOCIDOS
---------------------------------

Error:

    Table 'thesauce.contribucions' doesn't exist

Causa:
Eloquent infería el plural inglés contribucions desde el modelo
Contribucion, mientras la migración crea contribuciones.

Solución:
El modelo Contribucion declara:

    protected $table = 'contribuciones';

Error:

    Table 'thesauce.notificacions' doesn't exist

Causa:
El modelo Notificacion no tenía declarada la tabla española.

Solución:

    protected $table = 'notificaciones';

Error:

    Table 'thesauce.hitos_financieros' doesn't exist

Causa:
La migración activa crea hito_financieros en singular, mientras una versión
del modelo apuntaba a hitos_financieros.

Solución:
El modelo y la migración deben utilizar exactamente el mismo nombre.
En el proyecto activo se usa:

    hito_financieros

Error 404 en los módulos:

Causa:
Existían enlaces en el menú sin rutas correspondientes.

Solución:
Las 14 rutas administrativas están registradas en routes/web.php y el módulo
de carrito-detalles también está incluido.

Menú vacío:

Causa:
El layout mostraba enlaces, pero algunas páginas eran placeholders sin
controlador ni datos.

Solución:
Cada módulo tiene controlador, consulta Eloquent, página React y paginación.


19. AVISO DE NVM/HERD
---------------------

El mensaje:

    herd-load-nvmrc: command not found: nvm_find_nvmrc

proviene del entorno de Herd y NVM, no de Laravel ni de la base de datos.

No causa los errores de migración, seed ni autenticación.

Para corregir el entorno, se puede revisar que NVM esté cargado en ~/.zshrc:

    export NVM_DIR="$HOME/.nvm"
    [ -s "$NVM_DIR/nvm.sh" ] && source "$NVM_DIR/nvm.sh"

Después se debe abrir una nueva terminal.

22. FLUJO COMPLETO DE DATOS DE UN MÓDULO
-----------------------------------------

Ejemplo: módulo de contribuciones.

1. El usuario abre /admin/contribuciones.
2. routes/web.php dirige la petición a ContribucionController@index.
3. El middleware comprueba auth y verified.
4. ContribucionController consulta Contribucion.
5. with(['usuario', 'innovacion']) carga las relaciones.
6. paginate(10) agrega metadatos de páginas.
7. Inertia devuelve admin/contribuciones/index.
8. React recibe contribuciones como prop.
9. La tabla muestra usuario.nombre, innovacion.titulo, monto y estado.
10. Paginacion dibuja enlaces para cambiar de página.

Este mismo patrón se aplica al resto de módulos:

    Ruta -> Middleware -> Controlador -> Modelo/Relaciones
    -> Inertia -> Página React -> Tabla y paginación
