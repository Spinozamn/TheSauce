1. ESTructura GENERAL DEL PROYECTO
================================================================================

El proyecto TheSauce es una aplicación web full-stack construida con Laravel
(PHP) y React (frontend). Es una plataforma de crowdfunding/innovaciones donde
los usuarios pueden crear proyectos de financiación y recibir contribuciones.

Ubicación: /Users/manuel/Desktop/TheSauce

- /app         → Controladores, modelos, políticas y lógica PHP
- /routes      → Rutas de Laravel (web.php, api.php)
- /database    → Migraciones, seeders y factories de base de datos
- /frontend    → Aplicación React con Vite
- /public      → Archivos públicos y entrada point
- /storage     -> Almacenamiento de archivos y logs

TABLAS PRINCIPALES (15 tablas):

   - refresh_token (string, nullable)
   - expira_en (timestamp, nullable)

4. RELACIONES ENTRE ENTIDADES
================================================================================

Relaciones One-to-Many (1-n):
- usuario → roles (un usuario tiene un rol)
- usuario → cuentas_sociales (un usuario tiene múltiples cuentas sociales)
- usuario → innovaciones (un usuario crea múltiples innovaciones)
- innovación → hitos_financieros (una innovación tiene múltiples hitos)
- usuario → lista_deseos (un usuario tiene múltiples deseos)
- usuario → carritos (un usuario tiene un carrito)
- usuario → contribuciones (un usuario puede contribuir múltiples veces)
- usuario → comentarios (un usuario hace múltiples comentarios)
- usuario → notificaciones (un usuario recibe múltiples notificaciones)
- innovación → comentarios (una innovación tiene múltiples comentarios)
- innovación → logs_sistema (vía usuario_id opcional)

Relaciones Many-to-Many (n-m):
1. usuarios ↔ etiquetas (vía tabla etiqueta_innovacion)
   - Una usuario puede tener múltiples etiquetas
   - Una etiqueta puede estar en múltiples innovaciones

2. usuarios ↔ innovaciones (vía tabla lista_deseos)
   - Los usuarios pueden marcar innovaciones como deseos

3. innovaciones ↔ etiquetas (vía tabla etiqueta_innovacion)
   - Las innovaciones pueden tener múltiples etiquetas
   - Las etiquetas pueden estar en múltiples innovaciones

4. carritos ↔ innovaciones (vía tabla carrito_detalles)
   - Los carritos contienen múltiples innovaciones
   - Las innovaciones pueden estar en múltiples carritos

5. usuarios ↔ innovaciones (vía tabla contribuciones)
   - Los usuarios pueden contribuir a múltiples innovaciones
   - Las innovaciones pueden recibir múltiples contribuciones

Relaciones Auto-referenciales:
- comentarios → comentarios (comentario_padre_id)
   - Un comentario puede tener un comentario padre (respuesta anidada)
   - OnDelete: cascade en el padre

7. RESUMEN EJECUTIVO PARA LA ACTIVIDAD
================================================================================

Objetivo de la actividad:
Representar la información del proyecto mediante formatos XML y JSON,
utilizando el esquema de la base de datos del sistema. Los estudiantes
deberán comprender la estructura, organización y jerarquía de ambos
formatos, así como la representación de las relaciones entre entidades,
incluyendo relaciones Many-to-Many mediante objetos anidados.

Entidades a representar (15 totales):
1. roles - datos básicos de roles del sistema
2. usuarios - información de usuarios con relaciones a roles
3. cuentas_sociales - proveedores de autenticación social
4. categorías - clasificación de proyectos
5. etiquetas - etiquetas para innovaciones
6. innovaciones - proyectos de crowdfunding
7. etiqueta_innovacion - relación Many-to-Many (etiquetas↔innovaciones)
8. hitos_financieros - hitos de progreso financiero
9. lista_deseos - relación Many-to-Many (usuarios↔innovaciones)
10. carritos - carritos de compra
11. carrito_detalles - relación Many-to-Many (carritos↔innovaciones)
12. contribuciones - contribuciones financieras
13. comentarios - comentarios y respuestas anidadas
14. logs_sistema - auditoría del sistema
15. notificaciones - notificaciones al usuario

Requisitos cumplidos:
- ✅ Archivos JSON por cada tabla (3+ objetos cada uno)
- ✅ Archivos XML por cada tabla (misma información que JSON)
- ✅ Estructuras anidadas para relaciones Many-to-Many
- ✅ Validación de archivos XML y JSON
- ✅ Organización en carpeta específica (datos_intercambio/)

El proyecto utiliza Laravel Eloquent ORM con migraciones versionadas,
lo que permite una generación precisa del esquema relacional y su
representación en formatos de intercambio de datos.
